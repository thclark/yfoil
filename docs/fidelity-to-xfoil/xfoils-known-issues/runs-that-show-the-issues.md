# Runs that show the issues

Generated by `cargo run --release -p known-issues -- --docs` on 2026-10-15T13-24-43Z (git 9dd15f0, dirty, host aarch64-macos). Do not edit; regenerate. The run folder (`scripts/known-issues/runs/`, gitignored) holds `summary.json` with every point of every polar and `README.tex` with the same table for the paper.

Runs that show one of XFOIL's known issues ([the issue register](the-issue-register.md)) arising, and whether yFoil does the same: the reference hanging in its plot-label loop, the Kármán–Tsien pole, and the solution's and convergence's sensitivity to the panelling (a case run at N = 60, 160 and 240 panels, each with the iteration limit it was studied with). Each case's description names the section of the known issues it shows. The study is to grow until it shows every documented issue one for one.

Members are full polars or sets of points (`group = "known-issues"` in `xtask/fixtures-config/cases.toml`): a polar is XFOIL's polar procedure, 0 → +30°, `INIT`, 0 → −30° by 1° (`ALFA 0 / ASEQ`, ITMAX + 5 iterations per point, the sequence halting after NSEQEX = 4 consecutive unconverged points); an inviscid member is one SPECAL per alpha; a fixed-CL member one OPER `CL` command per point. yFoil is driven the same way through its `Session` and every point the reference recorded is compared — a viscous point with the studies' whole-run floor comparison (`scripts/study-support/records.rs`: iteration count, LVCONV, IST and ITRAN exact, every transient and the converged point within `max(tol · scale, FLOOR_FACTOR · floor)` with *floor* the reference's own 1-ULP spread of the value, *divergent* — [terminology](../../contributing/conventions/terminology.md) — where the reference itself moves by more than `DIVERGENCE_FLOOR`), an inviscid point on CL, CM, CDp and every node's γ, q and Cp at `TOL_SOLVER`. Every member is run with its five seeded 1-ULP twins (`twins = true`), so the table also says at which points XFOIL was itself ill-conditioned. The tests check the same behaviours minimally, one step at a time ([the test suite](../../contributing/the-test-suite.md)); this page demonstrates them.

The study follows each run past convergence: through stall, and into the region where the reference goes non-finite. The reference may record fewer points than the script — its sequence halted, or the fixture driver's watchdog ended a run that had gone non-finite and hung in XFOIL's plot-label loop ([known issues §4](../../fidelity-to-xfoil/xfoils-known-issues/the-issue-register.md)); yFoil's sweep continues to its own halt either way. A point is *followed to the end* when every one of its iterations agrees with the reference's within tolerance (or parts from it only where one of the reference's own 1-ULP twins had already parted earlier in the sweep); *parts at* is the first recorded point (leg, α) at which yFoil's iterations part from the reference's. Whether XFOIL is ill-conditioned there is measured on XFOIL alone, by its twins — five reruns of the reference with every panel coordinate jogged by −1, 0 or +1 ULP ([terminology](../../contributing/conventions/terminology.md)): where the largest spread of a value over the twins exceeds `DIVERGENCE_FLOOR`, a parting there is the expected consequence of an **ill-conditioned** solution; where the twins agree, a parting is a *mismatch*, settled by the one-step replay of CLAUDE.md Rule 3 — seed yFoil with XFOIL's exact state entering that SETBL call and require XFOIL's state after it at `TOL_SOLVER`. `tests/execution/steps.rs` replays every iteration of the calls where these sweeps part that way (`step_calls` in `cases.toml`), each value within the named tolerance or four times the step's own measured sensitivity, and `cargo xtask route` observes yFoil take XFOIL's route through each of those steps. Why a sweep parts where the reference is stable against its twins — MRCHDU's station Newton at a transition station amplifying its seed a thousandfold, which both codes follow iterate for iterate from the same state — is recorded with its measurements in [known issues §7.9](../../fidelity-to-xfoil/xfoils-known-issues/the-issue-register.md).

One figure per case: CL and CD against α (top), the last iteration's RMSBL and the iterations taken (second row), and the transition location x/c on the upper and lower side (third row, from XOCTR and yFoil's transition point; an open triangle marks a point whose final stagnation or transition station — IST, ITRAN — differs between the codes), and the position of transition within its station interval on each side (fourth row: 0 at station ITRAN − 1, 1 at station ITRAN; see the section on it below). For every case — the reference writes its final state of every VISCAL call (the per-node Cp, q and γ and the per-station XSSI, x, UEDG, THET, DSTR, CTAU, MASS and TAU, `viscal_state_<k>.dat`) a fifth row compares yFoil's final state of the point with the reference's array by array: the worst array's |Δ| as a ratio to its tolerance `max(TOL_SOLVER · scale, FLOOR_FACTOR · floor)` with the floor the reference's own 1-ULP twin's spread of that array at that call (left; the dotted line is the tolerance), and the |Δ| itself against that floor (right). That row is the accumulation measurement: a state that stays at the floor from point to point and then leaves it within one point has not accumulated anything. **XFOIL is red** (dashed, crosses), **yFoil blue** (solid line, circles), so any visible separation of the two colours is a difference between the codes. Each code is one trace; the fill of yFoil's circle says how its point compares: filled where every iteration of the point agrees with the reference's, hollow where yFoil's iterations part from the reference's within the point, or where the point comes after one that parted in the same leg — it then started from a state the reference did not compute, and its comparison is informational. An orange outer square marks a point during which that code went through a non-finite value: a station Newton whose residual was NaN (the iterate fallback then carries the march past it — for the reference, any `NaN` it printed during the call; for yFoil, its own count of such stations) or a non-finite RMSBL, CL, CD or CM in any iteration; where the plotted value is itself NaN and cannot be placed, an orange plus at the top of the panel marks its α. A black outer diamond marks a point within which yFoil parts from the reference where XFOIL is **ill-conditioned** (one of XFOIL's own twins parts there too: a divergent comparison, [terminology](../../contributing/conventions/terminology.md); the one-step replay from XFOIL's state at that iteration is the evidence that the step is faithful). A filled grey diamond marks a point within which yFoil parts where XFOIL is **well-conditioned** (its twins agree): a *mismatch*, to be settled by the same replay. Only the point at which a leg first parts carries a diamond; the points after it in the same leg carry none, because their comparison is informational. Where the red line stops short of the blue one the reference's sequence halted or hung there.

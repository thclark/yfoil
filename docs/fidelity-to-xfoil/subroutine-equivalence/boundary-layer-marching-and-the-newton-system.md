# Boundary-layer marching and the Newton system

The boundary-layer routines that march the stations and assemble and solve the global Newton
system, each loaded with XFOIL's exact state on entry and compared with XFOIL's state on exit.
All read the tracked reference case `naca0012_n60_a2_re1e6` (NACA 0012, 60 panels, α = 2°,
Re 1e6), regenerated by `cargo xtask fixtures --case naca0012_n60_a2_re1e6`, except SPECCL's.

| Routine | Test | What is compared |
| --- | --- | --- |
| MRCHUE, the first direct march with Ue prescribed | `tests/subroutine/mrchue.rs` | the BL state after the march (`mrchdu_input_1.dat`, written just before the first MRCHDU) and the per-iteration Newton trace (`xfoil_newton_trace.dat`), so the march can be forward-stepped station by station and the *first* divergent quantity reported |
| MRCHDU, the mixed march along the Ue–Hk characteristic | `tests/subroutine/mrchdu.rs` | for SETBL calls 1 to 3, the state before (`mrchdu_input_<k>.dat`) marched and compared with the state after (`mrchdu_output_<k>.dat`); on call 1 the Newton trace station by station, iteration by iteration |
| SETBL, the global Newton system | `tests/subroutine/setbl.rs` | on VISCAL iterations 1 to 3, every coefficient of VA/VB/VDEL/VM/VZ as BLSOLV receives it (`blsolv_input.dat`), from XFOIL's complete state entering SETBL's march; and what SETBL writes besides the system — ITRAN, XSSITR, TFORCE, XOCTR, YOCTR, TINDEX, DULE, USAV and the per-station TAU, DIS, CTQ, DELT, USLP (`setbl_output_<k>.dat`) |
| BLSOLV, the block elimination | `tests/subroutine/blsolv.rs` | **bit-identical**: 450 of 450 values on each of three calls. BLSOLV has no transcendentals, so with identical inputs and no fused multiply-add the result is the same bits on any IEEE-754 host |
| SPECCL, the inviscid alpha for a specified CL | `tests/subroutine/speccl.rs` | ALFA and CL entering VISCAL's loop (`viscal_inviscid.dat`) on `naca0012_n60_cl03_re1e6` |

Two notes on what these tests found:

- BLSOLV's test once asserted a relative error below 10, with a note about "~1 % errors that
  accumulate". The errors came from the test hard-coding the arc length as 2.0 instead of the
  fixture's 2.0387…, which shifted the sparse-skip thresholds by 2 % and flipped elimination
  decisions; the solver was never wrong ([known issues §7.2](../xfoils-known-issues/the-issue-register.md)).
  `tests/apparatus/blsolv_conditioning.rs` checks that those thresholds are far from their
  operands on the reference case, so the bit-identity is not a coincidence of rounding.
- The station Newton that MRCHUE and MRCHDU run, and the transition check inside it, are where
  most of XFOIL's quirks live: MRCHDU's locals persist across sides (§2.2), TRDIF reuses
  station-2 COMMON (§2.3), and MRCHUE's failure path calls BLVAR twice at a wake station (§7.11) —
  all replicated.

UPDATE, which applies the Newton step, is tested as the last step of a replayed VISCAL iteration:
[execution equivalence](../execution-equivalence/index.md).
